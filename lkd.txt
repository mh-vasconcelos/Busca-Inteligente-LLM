Recentemente, vi no podcast do IA Sob Controle que a Magalu publicou um paper detalhando como utilizaram LLMs para extrair atributos de produtos em escala (https://www.iasobcontrole.tech/206-desenvolvendo-o-ai-pave-br-no-luizalabs-com-caio-gomes-e-dr-murilo-gazzola/).



Resolvi testar uma ideia parecida com alguns produtos de higiene e beleza, focando em resolver um problema clássico do E-commerce: transformar títulos não estruturados em uma experiência de busca precisa.



A ideia era construir um motor de busca resiliente, baseado em dados validados pelos LLMs (Qwen para Feature Extraction e Gemini para criação de um dicionário de termos sinônimos)... Para isso, usei uma arquitetura em três etapas:



1. LLM-Based Feature Extraction (O Cérebro do ETL). A primeira barreira é estruturar o dado bruto. Em vez de criar centenas de regras de Regex, utilizei o Qwen (via Groq) para fazer a extração semântica. O modelo recebe títulos caóticos (ex: "Kit 3 Potes Creme Skala 1kg Expert Cachos") e devolve um JSON limpo e tabular: {'marca': 'Skala', 'linha': 'Expert', 'funcao': 'Cachos', 'volume': '1kg'}. Isso permitiu tratar cada atributo com o peso correto.



2. Normalização de Vocabulário (Gemini). Dados limpos não corrigem usuários que digitam errado. Utilizei o Gemini para gerar, de forma automatizada, mapas de sinônimos e correções fonéticas (o famoso mapper), garantindo que o sistema entenda que "esmaute" é "esmalte" e "risqui" é "Risqué".



3. Lógica Fuzzy Híbrida (Implementação). Com os dados estruturados pelo LLM, implementei um search engine em Python (Rapidfuzz) com uma lógica de "Scanner de Atributos".



O resultado é um pipeline que une a capacidade de interpretação dos LLMs com a velocidade da lógica Fuzzy determinística.
